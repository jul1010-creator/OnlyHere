## Real bugs fixed this session (don't reintroduce)

1. **`/api/perplexity` 405, root cause**: the file simply didn't exist in Oliver's local repo or on Vercel — a prior zip delivery never actually landed. Every Perplexity call was hitting Vercel's SPA catch-all rewrite (routes everything to `/`), which 405s a POST since it's serving a static file. Written directly into his repo now via device bridge.
2. **"Empty response from OpenAI" on Discover/town-event searches**: `gpt-5.6-sol` is a reasoning-tier model — `max_completion_tokens` is shared between its internal reasoning AND the visible reply, unlike older models. Two calls had genuinely tight budgets (300 and 500 tokens) that could get entirely eaten by reasoning, leaving zero for the actual answer. Bumped both to 1400, added retry, added `finish_reason`/`usage` logging to `askOpenAI` so this is provable at a glance if it recurs elsewhere.
3. **The "34 min walk that's really 7 min" map bug**: `resolveStopCoords` was checking a crude TOWN_COORDS substring match (e.g. "Odense Flower Festival" matching "Odense" → the town's generic center point) BEFORE checking for a real precise geocode, and `geocodeStopsForGuide` was skipping geocoding entirely for any stop that crude match already "resolved." Fixed: precise coordinates (real data, or an actual geocode using the place's own `mapHint` address) now always win over the generic town-center fallback, which is last-resort only.
4. Real weather (Yr.no, already being fetched for day badges) now also surfaces as a line in the guide's Essentials block when rain is genuinely likely on a real day — it was real data that just never got shown anywhere summary-level.
5. Flixbus/Kombardo Expresbus are now named proactively on any real intercity leg, not just as a fallback when a fare happens to be "genuinely expensive" (which is why Oliver never saw them mentioned).
