## Known architecture footgun: the tab pager breaks `position: fixed`
Every page (Home/Towns/Events/Food/Nightlife/etc) renders inside a shared strip (`stripRef` in App.jsx's PAGER) that uses `transform: translateX(...)` for the swipe animation. CSS spec: a transform on an ancestor becomes the containing block for any `position: fixed` descendant, so ANY fixed-position modal/sheet rendered as part of a tab's own content (not the top-level return, which sits outside the strip and is safe) will anchor to that giant multi-tab strip instead of the real screen and get clipped to a corner sliver. This is what caused "you click the filters and they jump to the corner." Fixed so far, via `createPortal(..., document.body)`: FilterChip's sheet (App.jsx), WeatherHeaderStrip's city popup. If a new fixed-position overlay gets added to any page's own content (not the modals already living at the bottom of GemlyxApp's return, past the PAGER close), it needs the same portal treatment or it WILL have this bug, even if it looks fine in isolation during dev.

## Hard performance rule (learned live, session end)
Clicking a filter chip on the live Events page froze painting for 30+ seconds (worse on phone). Root cause: willChange:transform on every card (a permanent GPU layer each, ~65 at once on the merged grid) plus backdrop-filter blur badges on every card (~130 live blurs). Both removed. NEVER put willChange or backdrop-filter on per-card/per-item elements in this app; blurs are allowed only on things that appear once and unmount (the entrance overlay). Badges over photos use solid rgba(10,15,30,0.9) instead.
